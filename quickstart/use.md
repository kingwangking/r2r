# R2R：最终到底怎么使用？

**R2R = Run to Ready。** 目标不是做一个新的开发 IDE，而是让现有 AI 编码工具学会：**完整规划、长程开发、同步轻量复核、跨会话延续、反复收敛到成熟产品**。

开发者无需掌握几十个命令，也不必先部署 Agent 调度服务器。**开始、继续、收敛** 是三个主要操作；你随时能插入问题、调整执行范围。

## 发布版怎么获取？

正式版本计划采用 **GitHub Releases + GitHub CLI 原生 Skill 安装**，不要求手动复制目录：

```bash
gh skill install kingwangking/r2r r2r --agent codex --scope user
```

**当前仓库仍为 Private，且还没有 Release；以上为正式发布后的使用方式，尚未实测安装成功。** 已获授权访问仓库的开发者仍可复制整个 Skill 目录或直接使用 Prompt。详见 [发行说明](../docs/product/distribution.md)。

## 1. 选择入口

- **最方便：直接复制下面的提示词**。适用于能访问项目的 ChatGPT、Codex、Claude Code 等。
- **经常使用：安装 [R2R Skill](../skills/r2r/SKILL.md)**。支持 Skill 的编码工具可以复用同一套操作规则，具体目录见 [安装说明](install.md)。

### 开始一个现有项目

```text
采用 R2R 开发当前项目。
先阅读真实仓库、现有规格和架构，建立覆盖完整产品的长期规划，
明确模块责任、关键风险与最终 READY 验收要求。
在项目根目录新建或更新 R2R.md，保存长期计划和当前执行状态；
不要覆盖已有规格，不要在不需要时制造大量治理文档。
随后直接开始第一个已授权、可安全执行的功能批次。
每个有意义的批次结束立即同步轻量自检，记录真实证据，
严重问题阻断受影响任务，普通问题登记后继续。
我可以随时调整执行长度、优先级、架构和审查深度。
会话结束前保存真实进度。未授权的合并、公开发布、
危险真实数据操作不执行；未运行的测试标记 NOT_RUN。
```

**第一次启动后应该看到什么？**

Agent 不是只回答“规划完成”，而是应当交付一个**实际生成或更新的 `R2R.md`**，明确目标、完整发展路线和下一轮工作，并在有执行权限的情况下马上实现第一批功能，留下真实提交或修改记录。

## 2. 日常操作：继续

```text
继续 R2R。读取当前真实 Git HEAD 和 R2R.md，核对现有成果、遗留问题与依赖，
不要重新从零规划。继续执行下一个安全的高价值功能批次，
同步轻量 Review 后继续。将真实结果和下一步写回 R2R.md。
```

可以连续运行很多批次；**批次长度由开发者指定或按当前信息判断**，不强制每 N 个任务 Review 一次。同步 Review 不是逐行深入审查。若执行会话或工具已经结束，只有在下一次真实启动后才能继续；R2R 不会偷偷后台执行。

## 3. 随时掌控：改变方向

例如：

```text
先暂停当前依赖任务，回答：正文持久化到底由哪个模块负责？
请给出代码或实际行为证据，检查是否重复实现。
如架构方向错了，先改 R2R.md 的设计决策，然后调整执行顺序。
其它真正独立、安全的任务可继续。
```

这类高信息价值的问题有时比一次全面 Review 更能避免巨大返工。

## 4. 产品成形：进入 HARDEN

```text
进入 R2R HARDEN。功能数量不是验收标准。
实际走通完整业务链，先解决结构、接口和数据权威问题；
然后分轮修复真实交互、持久化、恢复、异常权限、回归缺陷。
对每项承诺记录真实 PASS/FAIL/NOT_RUN 与测试的源代码/构建版本。
允许多轮结构性重组；未达到最终质量前不宣称 READY。
```

**什么时候完成？** 只有完整产品在约定范围内真正可用，核心风险和验证缺口达到接受条件，并经有权限的维护者批准，才可声明 READY。

## R2R.md 是什么？

一份放在**使用者自己项目根目录**的轻量长期计划与状态文件，不是本方法仓库的 `docs/program/current-state.md`。模板见 [`skills/r2r/assets/R2R.md`](../skills/r2r/assets/R2R.md)。

它尽量只保存三件事：**产品终点、长期路线、目前走到哪里以及下一步**。已有 spec、ADR 和 issue 直接链接复用，不复制重建。

## 最终实际交付给使用者的是

1. **能直接复制的 Prompt**：任何聊天工具可开始；能否真的修改项目取决于宿主权限。
2. **可搬运的 Agent Skill**：把方法打包给 Codex/Claude Code 等，不依赖 R2R 仓库内其他路径。
3. **R2R.md 单文件持续状态**：跨会话恢复与全局路线；不要求搭建服务器或数据库。
