# Quickstart — R2R needs no new tools

Use an existing specification/repository and your preferred AI coding agent. The method works from ChatGPT web with GitHub as well as local tools.

## 1. PLAN (copy)
```text
Use R2R. Read the real project facts and existing specs. Map all end-user journeys,
overall architecture, data authority and reuse candidates. Build a complete but
revisable product program and acceptance criteria. List uncertainty that would
make a long run wasteful. Distinguish facts from assumptions.
```

## 2. RUN (copy)
```text
Follow the R2R plan in my authorized scope. Keep implementing valuable user-facing
capabilities. After each meaningful batch, perform a short SYNCHRONOUS self-review;
deepen only for material risks. Do not demand exhaustive review or perfect intermediate smoke tests
before unrelated work. Keep actual commits/evidence/known risks and a resume pointer.
Stop affected unsafe operations, permission conflicts and irreversible risks.
Do not claim execution outside this active session.
```

## 3. STEER ANYTIME (examples)
- “What real user journey works, and where is the evidence?”
- “Does this duplicate an existing source of truth?”
- “Shorten the run; review the architecture of this shared data path first.”
- “The direction is clear; continue a long campaign with only cheap relevant checks.”
- “What would falsify the assertion that this module is integrated?”

## 4. HARDEN (copy)
```text
Make full-product readiness the current goal. Exercise actual user journeys;
correct major architecture and integration mismatches first, then fix failures,
run negative/restart/regression tests and repeat. Report NOT_RUN honestly.
Do not declare ready because the task list is complete or a shallow review passed.
```
